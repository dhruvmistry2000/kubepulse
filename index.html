Self-hosted · push-based

Every cluster, one pulse.

A read-only agent inside each cluster posts a snapshot to a dashboard you run. The browser never talks to the cluster. Nothing has to dial in.

Outbound only

The agent calls the dashboard every 30 seconds. Clusters do not open a port, a load balancer, or a firewall hole.

Read-only in the cluster

The agent lists Kubernetes objects. The only write is its own state Secret, and only in its namespace.

One place to look

GKE, EKS, AKS, and clusters on your own hardware share the same dashboard.

Three steps

Install the dashboard, then the agent.

  1. 01

    Run the dashboard

    The deploy script asks for the URL agents will call, plus an admin key and a viewer key. Keep a single copy. Live metrics sit in memory.

  2. 02

    Mint a token

    Open the dashboard, enter the admin key, and generate an install token for a cluster name. The token lasts 10 minutes.

  3. 03

    Helm-install the agent

    The chart registers once, stores a per-cluster credential, and heartbeats that name from then on. A new token is only for the first join.

In the dashboard

The snapshot, with the cost attached.

Agents send resource data. The dashboard adds price, history, and the views below. Pricing uses public lists and a bundled map. No cloud account keys.

  • Clusters

    Switch clusters from the sidebar. A cluster is healthy when its last heartbeat is under 90 seconds, measured on the dashboard clock.

  • Nodes and pods

    Capacity, allocatable, live CPU and memory, and the workload a pod belongs to. Filter by namespace, and hide system namespaces.

  • Cost and scaling

    Per-node and per-cluster cost, a node-count timeline, and retired nodes with their lifetime and accrued cost.

  • Workloads

    Deployments, services, ingresses, and ConfigMap key names. Cross-links jump from a pod to its node and deployment.

Install

Dashboard first. Agent second.

Dashboard

This asks for the dashboard URL and the keys, then starts the container or the Kubernetes deploy.

curl -fsSL -o deploy-dashboard.sh \
  https://dhruvmistry2000.github.io/kubepulse/deploy-dashboard.sh
chmod +x deploy-dashboard.sh
./deploy-dashboard.sh

From a checkout of the repo, ./scripts/deploy-dashboard.sh can also build the dashboard with Docker Compose.

Agent

Run this on the cluster after Add Cluster prints a token. The chart in this site is k8s-dashboard-agent.

helm repo add kubepulse https://dhruvmistry2000.github.io/kubepulse
helm install kubepulse-agent kubepulse/k8s-dashboard-agent \
  --set registrationToken=TOKEN \
  --set dashboardUrl=https://dashboard.example.com \
  --set clusterName=production
